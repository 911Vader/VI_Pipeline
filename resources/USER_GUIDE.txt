--------------------------------------------------------------------------------
1.  WHAT THIS PIPELINE DOES
--------------------------------------------------------------------------------

VI_Pipeline analyses genomic sequence data to identify and prioritise genetic
variants that may be relevant in a forensic or clinical context.

Given a set of raw reads (FASTQ) or an existing variant file (VCF), the
pipeline will:

  - Align reads to the GRCh38 human reference genome (FASTQ path only)
  - Call variants using DeepVariant, Google's deep-learning variant caller
  - Annotate every variant with functional consequence, population frequency,
    clinical significance (ClinVar), and in-silico pathogenicity predictions
    from multiple independent tools (CADD, REVEL, SpliceAI, AlphaMissense,
    dbNSFP, SIFT, PolyPhen-2)
  - Classify each variant according to ACMG/AMP 2015 criteria
  - Rank candidates by a composite priority score
  - Produce a PDF report, Excel spreadsheet, TSV, and JSON for further review

All annotation is performed locally. No data is sent to external servers.


--------------------------------------------------------------------------------
2.  SYSTEM REQUIREMENTS
--------------------------------------------------------------------------------

  Operating system    : Linux (Ubuntu 18.04 or later recommended)
  Python              : 3.10 or later
  RAM                 : 16 GB minimum (32 GB recommended for WGS)
  Disk space          : 200 GB for reference genome + VEP cache
                        ~55 GB for annotation databases (see Section 9)
                        ~50 GB working space per sample for FASTQ input
  Internet connection : Required on first run to pull the DeepVariant Docker
                        image (~1 GB). Not required after that.

Required tools (must be on your PATH or found during setup):

  Tool          Min. version   Purpose
  ------------- -------------- -----------------------------------------------
  docker        20.0           Runs DeepVariant variant caller
  vep           111            Variant Effect Predictor annotation engine
  bcftools      1.17           VCF normalisation (multi-allelic splitting)
  bgzip         1.17           VCF compression
  tabix         1.17           VCF indexing
  bwa           any            Read alignment to reference genome (FASTQ only)
  samtools      any            BAM sorting and indexing (FASTQ only)

Required external data:

  Resource              Notes
  --------------------- -------------------------------------------------------
  GRCh38 FASTA          Reference genome with .fai index (samtools faidx)
  VEP cache             Ensembl VEP offline cache, GRCh38 assembly
  BWA index             Pre-built index of GRCh38 FASTA (FASTQ input only)
                         Build with: bwa index genome.fa  (~1 hour)

3.  FIRST-TIME SETUP
--------------------------------------------------------------------------------

Run setup once before your first analysis. Setup will:
  - Locate all required tools and check their versions
  - Validate all configured resource paths
  - Write config/paths.yaml with the verified paths

Step 1 — Open config/paths.yaml and fill in the paths to your reference data.
         The resources section has a "notes" field for each entry explaining
         what file is needed:

           resources:
             reference_fasta:
               path: /data/reference/GRCh38.fa     # <-- edit this
             vep_cache_dir:
               path: /data/vep_cache                # <-- edit this
             bwa_index_prefix:
               path: /data/reference/GRCh38.fa      # <-- edit this (FASTQ only)

Step 2 — Run setup:

           python cli.py --setup

         If any check fails, the output explains exactly what is wrong and
         how to fix it. After fixing, re-run:

           python cli.py --setup --force

Step 3 — When you see "All required checks passed", setup is complete.

Note: Annotation resources (ClinVar, REVEL, SpliceAI, AlphaMissense, dbNSFP)
are optional but strongly recommended for full ACMG scoring. See Section 9.

4.  RUNNING THE PIPELINE
--------------------------------------------------------------------------------

4a.  DESKTOP GUI (recommended for new users)
---------------------------------------------

Launch the GUI:

    python launch_gui.py

The GUI window has the following fields:

  Input file          The VCF or FASTQ file to analyse.
                      Accepted formats:
                        - .vcf  .vcf.gz  .bcf        (variant call file)
                        - .fastq  .fastq.gz  .fq .fq.gz  (raw reads)
                      Click "Browse" to navigate to the file.
                      The Browse dialog opens at the VI_Pipeline folder by
                      default, but you can navigate anywhere on the system.

  R2 FASTQ            For paired-end FASTQ input only. Leave blank for:
  (optional)            - VCF input (field is automatically disabled)
                        - Single-end FASTQ input

  Gene list           A plain text file with one HGNC gene symbol per line.
                      The pipeline prioritises variants in listed genes and
                      always surfaces VUS variants in listed genes regardless
                      of rank (see Section 7).

  Output folder       Directory where all results will be written.
                      Must be inside the VI_Pipeline directory.
                      Created automatically if it does not exist.

  Sample ID           A unique identifier for this sample (e.g. SUD58).

  Case ID             Optional case reference number.
  (optional)

Click "Run Analysis". Progress is shown in the log panel at the bottom.
The pipeline may run for several hours for whole-genome FASTQ input.


4b.  COMMAND-LINE INTERFACE (CLI)
----------------------------------

VCF input (annotated or unannotated):

    python cli.py \
        --input  sample.vcf.gz \
        --gene-list  config/gene_list.txt \
        --output  runs/SUD58 \
        --sample-id  SUD58 \
        --case-id  CASE-001

FASTQ input — single-end:

    python cli.py \
        --input  sample.R1.fastq.gz \
        --gene-list  config/gene_list.txt \
        --output  runs/SUD58 \
        --sample-id  SUD58

FASTQ input — paired-end:

    python cli.py \
        --input   sample.R1.fastq.gz \
        --input2  sample.R2.fastq.gz \
        --gene-list  config/gene_list.txt \
        --output  runs/SUD58 \
        --sample-id  SUD58

Using a metadata file instead of inline flags:

    python cli.py \
        --input   sample.vcf.gz \
        --gene-list  config/gene_list.txt \
        --output  runs/SUD58 \
        --metadata  metadata.yaml

    metadata.yaml example:
        sample_id: SUD58
        case_id: CASE-001
        phenotype_terms: ["sudden unexplained death"]

All CLI options:

    --input,    -i FILE    Input file (VCF or FASTQ)
    --input2       FILE    R2 FASTQ for paired-end input
    --gene-list,-g FILE    Gene list file (default: config/gene_list.txt)
    --output,   -o DIR     Output directory (default: runs/)
    --sample-id    ID      Sample identifier
    --case-id      ID      Case identifier (optional)
    --metadata     FILE    YAML metadata file
    --verbose,  -v         Verbose logging
    --setup                Run setup checks
    --force                Force re-run of setup
    --version              Print version and exit


--------------------------------------------------------------------------------
5.  INPUT FILES
--------------------------------------------------------------------------------

VCF / VCF.GZ / BCF
  - Standard variant call format
  - May be annotated (VEP CSQ field present) or unannotated
  - If already annotated, VEP is skipped
  - Multi-allelic records are automatically split before annotation
  - Chromosome names must match your VEP cache (chr1 vs 1 — be consistent)
  - .vcf.gz files require a companion .tbi tabix index in the same directory
    (create with: tabix -p vcf sample.vcf.gz)

FASTQ / FASTQ.GZ  (and .fq / .fq.gz)
  - Raw sequencing reads (Illumina format)
  - Paired-end: provide R1 via --input and R2 via --input2
  - Single-end: provide only --input (R2 left blank or omitted)
  - Reads must have standard Illumina quality encoding (Phred+33)
  - The pipeline always runs VEP annotation on the variant calls it produces

GENE LIST
  - Plain text file, one HGNC gene symbol per line
  - Lines starting with # are treated as comments and ignored
  - Gene list is used for:
      * Boosting priority scores for in-list variants
      * Retaining tier-3 consequence variants that would otherwise be excluded
      * Surfacing VUS variants regardless of rank (see Section 7)


--------------------------------------------------------------------------------
6.  CONFIGURATION
--------------------------------------------------------------------------------

config/paths.yaml     (written by setup; resource paths go here)
  - Edit the resources.<name>.path fields to point to your files
  - Do not change the status or notes fields manually
  - After editing, re-run: python cli.py --setup --force

config/settings.yaml  (edit freely)
  - filtering:         AF cutoff, PASS requirement, consequence tiers
  - acmg:              which criteria are active, in-silico thresholds
  - ranking:           weights for each scoring component
  - vep:               fork count, timeout, extra flags
  - deepvariant:       Docker image version, model type, shards, timeout
  - reporting:         max candidates in PDF report

Key settings to review before your first run:

  filtering.max_af               Allele frequency cutoff (default 0.01 = 1%)
  vep.fork                       CPU threads for VEP (default 4)
  vep.timeout_hours              Abort VEP after this many hours (default 6)
  deepvariant.num_shards         CPU threads for DeepVariant (default 4)
  deepvariant.timeout_hours      Abort DeepVariant after this many hours (12)
  deepvariant.model_type         WGS or WES (default WGS)
  ranking.weights                Adjust scoring emphasis if needed

Current ranking weights (config/settings.yaml):

  Component               Weight   Notes
  ----------------------- -------- -----------------------------------------
  ACMG classification       40     P=100%, LP=80%, VUS=40%, LB=20%, B=0%
  ClinVar status            20     P/LP=100%, Conflicting=33%, B/LB=0%
  Gene list match           20     In list=100%, not in list=0%
  Rarity (gnomAD AF)        10     Novel/absent=100%, common=0% (linear)
  Consequence severity      10     Tier1=100%, Tier2=67%, Tier3=33%
  In-silico prediction       5     Mean of normalised CADD/REVEL/SpliceAI

7.  UNDERSTANDING THE OUTPUT
--------------------------------------------------------------------------------

All output files are written to the directory specified by --output.

File                        Description
--------------------------- ---------------------------------------------------
{sample_id}.pdf             PDF report — summary table, ranked candidates,
                             and VUS-in-listed-genes section (if applicable)

{sample_id}.xlsx            Excel spreadsheet with all retained variants,
                             sortable and filterable. Includes all annotation
                             fields and ACMG evidence codes.

{sample_id}.variants.tsv    Tab-separated values — same data as the spreadsheet.
                             Suitable for import into R, Python, or databases.

{sample_id}.json            Machine-readable JSON with full variant data,
                             pipeline metadata, and run parameters.

{sample_id}.vep.vcf         VEP-annotated VCF (if VEP was run). Contains the
                             full CSQ INFO field for downstream tools.

{sample_id}.norm.vcf        Normalised VCF after bcftools multi-allelic
                             splitting (if normalisation was performed).

{sample_id}.dv.vcf.gz       Raw DeepVariant output VCF (FASTQ input only).
                             Bgzipped. Input to VEP annotation.

{sample_id}.sorted.bam      Sorted, indexed BAM from BWA alignment.
                             (FASTQ input only)

{sample_id}.run.log.json    Machine-readable audit log: every pipeline step,
                             timestamp, warnings, and output file paths.

ACMG classification categories (from most to least pathogenic):
  Pathogenic (P)
  Likely Pathogenic (LP)
  Variant of Uncertain Significance (VUS)
  Likely Benign (LB)
  Benign (B)

Priority score:  0–100 composite score for ordering candidates.
  This is NOT a clinical diagnosis. It is a prioritisation aid only.


THE PDF REPORT
--------------

The PDF contains three main sections:

  1. Summary table
     Variant counts by ACMG category, total retained and excluded counts.

  2. Top candidates table (default: top 20 retained variants by priority score)
     Columns: Rank | Score | Gene | Chr:Pos Ref>Alt | HGVS c. | HGVS p. |
              Consequence | ACMG | Codes | gnomAD AF | ClinVar
     The "Chr:Pos Ref>Alt" column (e.g. chr1:12345678 C>T) gives you the
     exact information needed to look up a variant in ClinVar or other
     databases. If HGVS c. is populated, use that for the most precise search.

  3. VUS in Listed Genes (only shown when applicable)
     Any variant classified as VUS that is in your gene list but did NOT
     make the top-N cut will appear here unconditionally.
     These variants remain classified as VUS — the ACMG classification has
     NOT been changed. They require expert review. This section exists
     because a VUS in a forensically relevant gene (e.g. RYR1, SCN5A,
     KCNQ1) may be clinically meaningful even without sufficient evidence
     for reclassification.

     Important: ACMG/AMP 2015 defines VUS as a variant where current
     evidence is insufficient to classify as pathogenic or benign. A VUS
     is not benign. Expert clinical judgment is required.

9.  ANNOTATION RESOURCES
--------------------------------------------------------------------------------

The pipeline uses a layered annotation strategy. The resources below are
all configured at the standard installation location:
  /mnt/server_share/Reference_Material/annotation/

Resource          Status         ACMG codes     What it adds
----------------- -------------- -------------- ----------------------------
CADD (SNV+indel)  CONFIGURED     PP3, BP4       Deleteriousness phred score;
                                                 phred >= 20 -> damaging
ClinVar           CONFIGURED     PS3            Clinical significance and
                                                 review status; P/LP with
                                                 >=2 stars triggers PS3
REVEL             CONFIGURED     PP3, BP4       Missense ensemble score;
                                                 >= 0.75 -> pathogenic,
                                                 <= 0.15 -> benign
AlphaMissense     CONFIGURED     (annotation)   DeepMind structural missense
                                                 classifier; am_pathogenicity
                                                 score added to reports
SpliceAI (SNV)    DOWNLOADING    PP3, BP4       Deep-learning splice impact;
                                                 max delta >= 0.5 -> high
                                                 impact; <= 0.1 -> none
                                                 NOTE: SNV-only (indel file
                                                 requires Illumina BaseSpace)
dbNSFP 4.1a       DOWNLOADING    (annotation)   30+ prediction tools in one
                                                 file: PolyPhen-2, SIFT,
                                                 MutationTaster, MetaRNN, etc.
                                                 Added to reports; does not
                                                 directly change ACMG class
SIFT              BUILT-IN       (annotation)   VEP built-in; no file needed
PolyPhen-2        BUILT-IN       (annotation)   VEP built-in; no file needed

To re-annotate a sample after a new resource is added:
  1. Delete the cached annotated VCF for that sample:
       rm runs/{SAMPLE}/{SAMPLE}.vep.vcf
  2. Re-run the pipeline — VEP will pick up all configured resources.

VEP skips re-annotation if {sample}.vep.vcf already exists and contains a
valid CSQ header (controlled by vep.skip_if_annotated_exists in settings.yaml).


ADDING SPLICEAI INDEL COVERAGE
  The SpliceAI indel file (~2 GB) is hosted on Illumina BaseSpace:
    1. Create a free account at basespace.illumina.com
    2. Accept the dataset share: basespace.illumina.com/s/otSPW8hnhaZR
    3. Download with the BaseSpace CLI:
         bs dataset download --id <datasetid> -o /mnt/server_share/Reference_Material/annotation/
    4. Set resources.spliceai_indel_file.path in config/paths.yaml
    5. Re-run: python cli.py --setup --force

10. TROUBLESHOOTING
--------------------------------------------------------------------------------

"Setup required"
  Run python cli.py --setup before running an analysis.

"VEP executable not found"
  VEP is not installed or not on your PATH.
  Install via: conda install -c bioconda ensembl-vep

"Tabix index not found" for VCF.GZ input
  Run: tabix -p vcf your_sample.vcf.gz
  This creates the required .tbi index file alongside your VCF.

"BWA index not found"
  Build the index: bwa index /path/to/genome.fa
  Or set resources.bwa_index_prefix.path in config/paths.yaml.

"DeepVariant timed out"
  Increase deepvariant.timeout_hours in config/settings.yaml.
  Or increase deepvariant.num_shards to use more CPU threads.

"VEP annotation timed out"
  Increase vep.timeout_hours in config/settings.yaml.
  Increase vep.fork to use more CPU threads.
  For very large VCFs, split by chromosome first:
    bcftools view -r chr1 input.vcf.gz -Oz -o chr1.vcf.gz
    tabix -p vcf chr1.vcf.gz

"0 variants parsed"
  The annotated VCF may be empty, or VEP may have filtered all records.
  Check {sample_id}.vep.vcf for content.
  Check {sample_id}.run.log.json for warnings.

"R2 FASTQ is only valid for FASTQ input" (GUI)
  You have typed an R2 path for a VCF input file.
  Clear the R2 field, or change the input to a FASTQ file.

"No ClinVar status shown in PDF"
  ClinVar must be configured in config/paths.yaml and the sample must be
  re-annotated (delete the cached .vep.vcf and re-run).

"No Pathogenic findings, only Likely Pathogenic or VUS"
  This is expected if ClinVar is not yet configured or the sample was
  annotated before ClinVar was added. Pathogenic requires PS3 (ClinVar
  P/LP with >=2-star review) combined with other pathogenic evidence.
  After configuring ClinVar and re-annotating, variants with published
  pathogenic interpretations will be reclassified automatically.

"VUS in listed gene not appearing in main PDF table"
  VUS variants in your gene list that rank below the top-N candidates
  will appear in the dedicated "VUS in Listed Genes" section at the
  bottom of the PDF. They are not excluded — they are surfaced separately.

Results look unexpected
  Review config/settings.yaml — particularly filtering.max_af,
  filtering.require_pass, and acmg.active_criteria.
  Check the run log JSON for warnings about misconfigured resources.

For further assistance, check the run log:
  {output_dir}/{sample_id}.run.log.json
