## 2. GUI — Advanced Subset Filter Panel

### What it is
A new collapsible panel at the bottom of the main window. The user sets criteria **before clicking Start Analysis** — the custom filter then runs automatically as the final step of every pipeline run, producing an additional output file alongside the standard subsets.

### Criteria available

| Criterion | Operator | Default threshold |
|-----------|----------|-------------------|
| CADD phred | ≥ | 20 |
| REVEL score | ≥ | 0.75 |
| SpliceAI max delta | ≥ | 0.5 |
| AlphaMissense | ≥ | 0.564 |
| gnomAD AF | ≤ | 0.001 |
| LOFTEE | HC only | — |
| Canonical transcript | Only | — |
| In gene list | Match | — |
| ClinVar | P/LP/Conflicting · P/LP only · Conflicting only | — |

- **Match mode:** ALL criteria (AND) or ANY criterion (OR)  
- **Output:** written to `runs/<sample>/vep_filter/subsets/<name>.vcf.gz` alongside all standard subsets

### Pipeline flow with custom filter

```
Input (FASTQ / VCF / BAM)
        │
        ▼
Stage 1 — VEP annotation (or skip if already annotated)
        │
        ▼
Stage 2 — vep_filter.sh → 6 standard subsets
        │
        ▼
Stage 3 — Custom subset filter (if criteria configured)
        │
        ▼
Reports (PDF · TSV · JSON · XLSX)
```

The **Apply Filter** button in the panel still works independently for re-filtering a previous run without re-running the whole pipeline.

## 4. Bash — ClinVar Filter Bug Fix

### The bug
The bcftools filter in `vep_filter.sh` used:
```bash
-i 'ClinVar_CLNSIG~"Pathogenic"'
```
This is **case-sensitive**. ClinVar stores the value as `Likely_pathogenic` (lowercase 'p'), so the filter matched `Pathogenic` but **silently missed `Likely_pathogenic`**.

### The fix
```bash
-i 'ClinVar_CLNSIG~"[Pp]athogenic"'
```
Both `Pathogenic` and `Likely_pathogenic` (and `Conflicting_interpretations_of_pathogenicity`) are now caught.

### Impact
Without this fix, ClinVar Likely Pathogenic variants were absent from the `clinvar_plp.vcf.gz` subset — a silent false negative that would not produce any error message.

## 5. Bash — Non-Canonical Gene List Subset

### What changed
The pipeline now produces **two** gene list subset files instead of one:

| File | Contents |
|------|----------|
| `subsets/gene_list_canonical.vcf.gz` | Variants in listed genes — canonical transcript only |
| `subsets/gene_list_noncanonical.vcf.gz` | Variants in listed genes — all non-canonical transcripts |

### Why it matters
The canonical transcript is Ensembl's administrative choice and may not reflect the clinically relevant isoform. A pathogenic variant in a disease-relevant alternative isoform would be invisible if only canonical transcripts were examined. The non-canonical file catches these cases for manual review.

## 6. Bash — Case-Insensitive Gene List Matching

### The bug
`bcftools +split-vep` with `SYMBOL=@gene_list.txt` is **case-sensitive**. VEP always outputs gene symbols in uppercase (e.g., `BRCA1`). A gene list file with mixed-case entries (e.g., `Brca1`) would silently produce zero matches.

### The fix
Before running bcftools, the script now converts the gene list to uppercase in a temporary file:
```bash
GENE_LIST_UC="$(mktemp)"
tr '[:lower:]' '[:upper:]' < "$GENE_LIST" > "$GENE_LIST_UC"
```
The temporary file is cleaned up automatically when the script exits.

## 7. PDF Report — Cell Overflow Fix

### The bug
Long strings (HGVS notation, ClinVar text, consequence names) were wider than their table columns and overflowed into adjacent cells, making the PDF unreadable.

### The fix
Every table cell is now wrapped in a ReportLab `Paragraph` object with `wordWrap="CJK"`. CJK wrapping breaks text at any character when no space is present — essential for HGVS strings like `NM_000059.3:c.1813dup` which have no natural word boundaries.

```
Before:  NM_000059.3:c.1813dup|overflows into next column|
After:   NM_000059.3:
         c.1813dup
```

## 9. Validation — NA12878 Download

### What is NA12878
NA12878 (also called HG001) is the **gold standard reference sample** for validating genomic pipelines, produced by the NIST Genome in a Bottle (GIAB) Consortium. It is a real human genome sequenced with 10+ different technologies and independently verified at millions of positions.

### What is being downloaded

| File | Source | Size | Purpose |
|------|--------|------|---------|
| `ERR194147_1.fastq.gz` | ENA (EBI) | 51 GB | R1 reads — 30× Illumina WGS of NA12878 |
| `ERR194147_2.fastq.gz` | ENA (EBI) | 53 GB | R2 reads |
| `HG001_GRCh38_1_22_v4.2.1_benchmark.vcf.gz` | NIST/NCBI | ~500 MB | Truth VCF — known correct variant calls |
| `HG001_GRCh38_1_22_v4.2.1_benchmark.vcf.gz.tbi` | NIST/NCBI | small | Index |
| `HG001_GRCh38_1_22_v4.2.1_benchmark_noinconsistent.bed` | NIST/NCBI | ~30 MB | High-confidence genomic regions |

All files are stored in:
```
/mnt/server_share/Reference_Material/validation/NA12878/
```
Can be deleted cleanly with `rm -rf` on that folder — nothing else is affected.

### Validation plan (next step)
1. Run VI_Pipeline on NA12878 FASTQs end-to-end
2. Compare output VCF against GIAB truth set using `hap.py`
3. Measure: **Precision, Recall, F1** for SNVs and INDELs separately
4. Benchmark targets: SNV precision ≥ 99.5%, recall ≥ 99.5%
