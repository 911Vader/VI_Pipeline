## 1. Sambamba installed and configured for duplicate marking

**What:** Installed sambamba 0.6.6 via conda (bioconda channel).

**Why:** sambamba is the fastest duplicate marking tool — fully multithreaded vs
samtools markdup's single-threaded detection. It was added as the preferred tool
in the markdup step added in a previous session.

**Config change (`config/settings.yaml`):**
```yaml
deepvariant:
  markdup_tool: "sambamba"
  remove_duplicates: true
  markdup_timeout_hours: 0
```

## 4. FASTQ pair synchronisation replaced: fastp → seqkit pair

**What:** Replaced fastp with `seqkit pair` as the primary FASTQ synchronisation
tool. fastp is retained as a fallback if seqkit is unavailable.

**Why — pipeline run failed with:**
```
ERROR: input files don't contain identical amount of reads
Read1 pack size: 204 / Read2 pack size: 1000  (at pack 789293)
```

ERR194147 R1 has 789,297,204 reads and R2 has 789,353,412 reads — a difference
of 56,208 reads. fastp requires equal total read counts in paired mode and
hard-fails when they differ. The root cause was missing R1 reads from the ENA
download, not just mid-file name mismatches as previously assumed.

seqkit pair matches reads by name and discards unpaired reads, handling both:
- Files with different total read counts (ERR194147's case)
- Mid-file orphaned reads (equal counts but desynced names)

**Impact of discarding 56,208 reads:** 0.007% of total reads. These are R2
reads with no matching R1 — unusable in paired-end mode regardless. No
detectable effect on coverage or variant calling.

**Code changes (`analysis/upstream/fastq_handler.py`):**
- Added `_run_seqkit_pair()` function
- Step 0 now tries seqkit first, falls back to fastp with a warning
- Fixed fastp thread cap: enforced `min(16, threads)` (fastp internal max is 16)

**Stale files removed:** Incomplete synced files written by the failed fastp run
(`HG001.r1.synced.fastq.gz`, `HG001.r2.synced.fastq.gz`) were deleted to
prevent the resume logic from skipping the sync on the next run.
