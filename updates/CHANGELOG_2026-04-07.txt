I.   PROJECT SCAFFOLD
Files: cli.py, config/settings.yaml, config/paths.yaml, requirements.txt,
       run_pipeline.sh, analysis/__init__.py, reporting/__init__.py

Built:
  - Top-level directory structure (analysis/, config/, gui/, reporting/,
    setup/, tests/, updates/)
  - settings.yaml: filtering rules, VEP plugin config, ACMG thresholds,
    DeepVariant settings, reporting options
  - paths.yaml: auto-generated by setup module; stores found/missing status
    for every external tool and reference file — never edited by hand
  - run_pipeline.sh: shell entry-point wrapper around cli.py
  - requirements.txt: pinned Python dependencies

--------------------------------------------------------------------------------

II.  SETUP MODULE
Files: setup/tool_checker.py, setup/config_writer.py,
       setup/resource_checker.py, setup/setup_runner.py

Built:
  - First-run setup system that validates the environment before any analysis
  - tool_checker: detects VEP, BWA, samtools, DeepVariant (Docker), bcftools
  - resource_checker: locates all annotation reference files —
      Reference FASTA + index, dbNSFP, CADD (SNV + indel), REVEL,
      SpliceAI SNV, ClinVar VCF + index, AlphaMissense
  - config_writer: writes paths.yaml with path and found/missing status
    for every resource; consumed by annotator and fastq_handler at runtime
  - setup_runner: orchestrates the full check and prints a readable report
    listing which tools and files are ready and which are missing

--------------------------------------------------------------------------------

III. ACMG CLASSIFIER
Files: analysis/acmg/evidence_codes.py, analysis/acmg/rules.py,
       analysis/acmg/classifier.py

Built:
  - ACMG/AMP 2015 variant classification system (Richards et al., Table 5)
  - evidence_codes.py: defines weight constants (VERY_STRONG, STRONG,
    MODERATE, SUPPORTING) and combination logic that maps evidence totals
    to Pathogenic / Likely Pathogenic / VUS / Likely Benign / Benign
  - rules.py: implements each active criterion as an eval_*() function:
      PVS1 — null variant (requires LOFTEE HC)
      PS3  — ClinVar review status proxy (expert panel / multiple submitters)
      PM2  — absent or extremely rare in gnomAD
      PM4  — protein length change via in-frame indel
      PP3  — multiple in-silico tools predict damaging
      BA1  — AF > 5% (stand-alone benign)
      BS1  — AF greater than expected for disorder
      BP4  — multiple in-silico tools predict benign
      BP7  — synonymous with no predicted splice impact
  - classifier.py: applies all active rules, accumulates evidence weights,
    and returns a classification + list of fired criteria

--------------------------------------------------------------------------------

IV.  VCF PROCESSING
Files: analysis/vcf_validator.py, analysis/vcf_normalizer.py,
       analysis/annotator.py, analysis/parser.py

Built:
  - vcf_validator: checks VCF index presence, genome build (GRCh38),
    required FORMAT and FILTER fields, and PASS variant count
  - vcf_normalizer: runs bcftools norm to left-align indels and split
    multi-allelic sites; output written to a normalised VCF before annotation
  - annotator: constructs and runs the full VEP CLI command with:
      Plugins — CADD, REVEL, SpliceAI (SNV), dbNSFP (REVEL, MetaSVM,
                PolyPhen2, SIFT, MutationTaster), LOFTEE, AlphaMissense
      Custom  — ClinVar VCF injected into CSQ via --custom
      Flags   — --vcf, --fork, --distance, --no_stats, assembly GRCh38
    Enforces a configurable timeout. Optionally skips re-annotation if the
    output VCF already exists (skip_if_annotated_exists: true).
  - parser: reads the annotated VCF line by line; extracts the VEP CSQ
    block and populates a typed Variant dataclass covering:
      consequence, gene symbol, transcript, gnomAD AF, in-silico scores
      (CADD, REVEL, SpliceAI, MetaSVM, PolyPhen2, SIFT, MutationTaster,
       AlphaMissense), ClinVar fields (significance, review status, disease),
      LOFTEE status, zygosity, and inheritance mode

--------------------------------------------------------------------------------

V.   FILTER ENGINE AND RANKER
Files: analysis/filter_engine.py, analysis/ranker.py

Built:
  - filter_engine.apply_filters(): applies consequence tier rules, gene-list
    tagging, allele frequency cutoffs, PASS filter, and ClinVar benign logic
    - Excluded tier consequences (intergenic, upstream, downstream) -> excluded
    - BA1 (AF > 5%) -> excluded
    - ClinVar benign/likely-benign -> excluded
    - Tier-3 variants (synonymous, UTR, intronic) outside gene list -> excluded
    - Variants failing PASS filter -> excluded
  - ranker.rank_variants(): scores retained variants using a weighted
    combination of ACMG classification, consequence tier, in-silico evidence,
    ClinVar significance, and gene-list membership

--------------------------------------------------------------------------------

VI.  UPSTREAM INPUT HANDLING
Files: analysis/input_router.py, analysis/upstream/fastq_handler.py,
       analysis/upstream/bam_handler.py

Built:
  - input_router: auto-detects input type (VCF / BAM / FASTQ) by file
    extension and header inspection; routes to the appropriate handler
  - fastq_handler: runs the FASTQ -> VCF pipeline:
      1. BWA MEM alignment + samtools sort/index -> sorted BAM
      2. DeepVariant variant calling inside the official Docker container
         (google/deepvariant:<version>); num_shards and timeout configurable
      3. Returns path to the DeepVariant output VCF for downstream annotation
  - bam_handler: accepts an existing aligned BAM, validates it, and runs
    DeepVariant directly (skipping the BWA alignment step)

--------------------------------------------------------------------------------

VII. CLINGEN INTEGRATION
File: analysis/clingen.py

Built:
  - Queries the ClinGen Allele Registry to resolve variant identifiers
  - Queries the ClinGen Gene Validity API to fetch gene–disease assertions
    (Definitive, Strong, Moderate, Limited, No Known Disease Relationship)
  - Results surfaced in variant.clingen_gene_validity field
  - Used by reviewer flags to provide gene–disease context

--------------------------------------------------------------------------------

VIII. REPORTING
Files: reporting/run_log.py, reporting/spreadsheet.py, reporting/tsv_export.py,
       reporting/json_export.py, reporting/pdf_report.py

Built:
  - run_log: records each pipeline step (name, status, timestamp, optional
    message); written to the run output directory as a JSON log file
  - spreadsheet: Excel workbook with two sheets — Candidates and Excluded;
    columns cover position, gene, consequence, ACMG classification, gnomAD AF,
    in-silico scores, ClinVar, zygosity, exclusion reason
  - tsv_export: tab-separated flat export of the same variant data
  - json_export: structured JSON export for downstream tooling
  - pdf_report: printable PDF with sample metadata, pipeline version,
    top N candidates (configurable), and mandatory clinical disclaimer

--------------------------------------------------------------------------------

IX.  GUI
Files: gui/app.py, gui/runner.py, gui/validation.py, launch_gui.py

Built:
  - tkinter GUI providing a point-and-click interface to the pipeline
  - Input section: file pickers for VCF / BAM / FASTQ, sample ID, case ID,
    gene list, phenotype terms, output directory
  - Settings panel: model type (WGS/WES), genome build, num_shards
  - Run Analysis button triggers the pipeline via cli.py in a background thread
  - Scrolling log panel streams stdout/stderr in real time
  - Status bar shows current state (Running / Completed / Failed)
  - runner.py: runs the CLI subprocess in a daemon thread; forwards stdout
    lines to a queue consumed by the GUI on each tick
  - validation.py: checks required fields and file existence before run
  - launch_gui.py: standalone entry point (python launch_gui.py)
