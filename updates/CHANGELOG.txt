2026-04-07 to 2026-04-30 — Initial Pipeline Build
================================================================================

I.   Project Scaffold
     Files: cli.py, config/settings.yaml, config/paths.yaml, requirements.txt,
            run_pipeline.sh, analysis/__init__.py, reporting/__init__.py
     Built: Core directory structure, settings.yaml (filtering rules, VEP config,
            ACMG thresholds), paths.yaml (auto-generated by setup module),
            run_pipeline.sh entry-point wrapper, requirements.txt.

II.  Setup Module
     Files: setup/tool_checker.py, setup/config_writer.py,
            setup/resource_checker.py, setup/setup_runner.py
     Built: First-run setup system that detects VEP, BWA, samtools, DeepVariant,
            and all annotation files (reference FASTA, dbNSFP, CADD, REVEL,
            SpliceAI SNV, ClinVar VCF). Writes paths.yaml with found/missing
            status for each resource. setup_runner orchestrates the full check
            and produces a human-readable report.

III. ACMG Classifier
     Files: analysis/acmg/evidence_codes.py, analysis/acmg/rules.py,
            analysis/acmg/classifier.py
     Built: ACMG/AMP 2015 evidence-code system (PVS1, PS3, PM2, PM4, PP3,
            BA1, BS1, BP4, BP7). evidence_codes.py defines weight constants and
            combination logic per Table 5. rules.py implements each criterion
            as an eval_*() function. classifier.py applies all active rules and
            returns Pathogenic / Likely Pathogenic / VUS / Likely Benign / Benign.

IV.  VCF Processing
     Files: analysis/vcf_validator.py, analysis/vcf_normalizer.py,
            analysis/annotator.py, analysis/parser.py
     Built: vcf_validator checks index, genome build, and FILTER/FORMAT fields.
            vcf_normalizer left-aligns and splits multi-allelic sites via bcftools.
            annotator constructs and runs the VEP CLI command with plugins:
            CADD, REVEL, SpliceAI (SNV), dbNSFP (REVEL, MetaSVM, PolyPhen2,
            SIFT, MutationTaster), LOFTEE, ClinVar (--custom), AlphaMissense.
            parser extracts the VEP CSQ block into a typed Variant dataclass
            covering consequence, gene, gnomAD AF, in-silico scores, ClinVar
            fields, LOFTEE status, zygosity, and inheritance.

V.   Filter Engine and Ranker
     Files: analysis/filter_engine.py, analysis/ranker.py
     Built: filter_engine applies consequence tiers, gene list, allele frequency
            cutoffs (BA1 > 5% excluded), PASS filter, and ClinVar benign
            exclusion. ranker scores retained variants by ACMG classification,
            consequence tier, in-silico evidence, and gene-list membership.

VI.  Upstream Input Handling
     Files: analysis/input_router.py, analysis/upstream/fastq_handler.py,
            analysis/upstream/bam_handler.py
     Built: input_router detects VCF / BAM / FASTQ input automatically.
            fastq_handler runs BWA MEM + samtools sort/index, then launches
            DeepVariant inside its official Docker container (google/deepvariant).
            bam_handler validates and re-calls variants from an existing BAM.

VII. ClinGen Integration
     File: analysis/clingen.py
     Built: Queries the ClinGen Allele Registry and Gene Validity API to fetch
            gene–disease assertions and cross-check variant identifiers.

VIII. Reporting
     Files: reporting/run_log.py, reporting/spreadsheet.py, reporting/tsv_export.py,
            reporting/json_export.py, reporting/pdf_report.py
     Built: run_log records each pipeline step with timestamps.
            spreadsheet writes an Excel workbook (two initial sheets: Candidates,
            Excluded). tsv_export and json_export provide machine-readable outputs.
            pdf_report generates a printable PDF with sample metadata, top
            candidates, and the mandatory disclaimer.

IX.  GUI
     Files: gui/app.py, gui/runner.py, gui/validation.py, launch_gui.py
     Built: tkinter GUI with file-picker inputs (VCF / BAM / FASTQ), sample-ID
            and gene-list fields, settings controls, and a scrolling log panel.
            runner.py runs the CLI in a background thread and forwards stdout
            lines to the GUI queue. validation.py checks required fields before
            allowing a run. launch_gui.py is the entry point.

X.   Test Suite
     Files: tests/ (all subdirectories mirroring the source tree)
     Built: pytest suite covering all modules. 931 tests passing at end of
            initial build phase (2026-04-30 baseline).

2026-04-30 — Annotation Bug Fixes
================================================================================

1. REVEL Plugin Argument Fix
   File: analysis/annotator.py
   Problem: Pipeline passed "grch38" as a second argument to the REVEL plugin.
            REVEL.pm interprets the second positional arg as "no_match" (a flag
            to suppress unmatched variants), not as an assembly selector. This
            caused REVEL scores to be silently dropped.
   Fix: Removed the erroneous "grch38" argument.
        Plugin call changed from:
          --plugin REVEL,<file>,grch38
        to:
          --plugin REVEL,<file>

2. MetaRNN → MetaSVM (dbNSFP column mismatch)
   Files: analysis/annotator.py, analysis/parser.py, reporting/spreadsheet.py,
          config/settings.yaml
   Problem: Pipeline requested MetaRNN_score from dbNSFP 4.1a, but that column
            does not exist in this version. No scores were returned.
   Fix: Replaced MetaRNN_score with MetaSVM_score + MetaSVM_pred throughout.
        - settings.yaml: dbnsfp_columns updated
        - parser.py: Variant dataclass field renamed metarnn_score -> metasvm_score,
          metasvm_pred added
        - spreadsheet.py: column renamed "MetaRNN" -> "MetaSVM", added "MetaSVM Pred"

3. ClinVar Fields Always Empty
   File: analysis/parser.py
   Problem: Parser called _extract_clinvar(info_dict), reading ClinVar from the
            VCF INFO column. However, VEP --custom injects ClinVar fields inside
            each per-transcript CSQ entry, not as standalone INFO keys.
            Result: clinvar_significance, clinvar_review_status, clinvar_disease
            were always None, so PS3 never fired and ClinVar column was blank.
   Fix: Changed to read ClinVar from primary.raw (the CSQ transcript dict):
          clinvar_raw = primary.raw if primary else {}
        Also updated test_clinvar_from_info_field -> test_clinvar_from_csq_field
        to match the correct VEP output format.

4. SpliceAI Plugin Crash (SpliceAI.pm)
   File: ~/.vep/Plugins/SpliceAI.pm
   Problem: SpliceAI.pm called add_file($param_hash->{indel}) unconditionally.
            When only the SNV file was configured (indel = undef), this triggered
            a fatal "No file specified" error and the entire VEP run failed.
   Fix: Added defined() guards:
          $self->add_file($param_hash->{snv})   if defined($param_hash->{snv});
          $self->add_file($param_hash->{indel}) if defined($param_hash->{indel});

5. SpliceAI Scores Not Parsed (Wrong Location)
   File: analysis/parser.py
   Problem: SpliceAI VEP plugin writes delta scores to INFO fields (e.g.
            SpliceAI_pred_DS_AG) when VEP runs in --vcf mode. The parser was
            reading spliceai_max_ds from the CSQ transcript dict, where no
            SpliceAI data was present. SpliceAI column was always empty.
   Fix: Added _extract_spliceai_max(info_dict) that reads from INFO first,
        falls back to CSQ for VCFs from other toolchains:
          spliceai_info = _extract_spliceai_max(info_dict)
          v.spliceai_max_score = spliceai_info if spliceai_info is not None
                                 else primary.spliceai_max_ds

2026-05-05 — Performance, GUI, ACMG, Reporting
================================================================================

7. BWA Alignment Timeout Fix
   Files: analysis/upstream/fastq_handler.py, config/settings.yaml
   Problem: BWA used 4 threads (from deepvariant.num_shards). On this 192-core
            server, a 1.5 GB FASTQ timed out after 12 hours.
   Fix: Added separate bwa_threads: 32 and bwa_timeout_hours: 6 settings.
        BWA now completes in ~20-40 minutes. Timeout error message names the
        exact settings to change. bwa_threads is independent of num_shards
        (BWA runs on the host; DeepVariant runs inside Docker).

8. Stop Analysis Button (GUI)
   Files: gui/app.py, gui/runner.py
   Problem: No way to cancel a running analysis from the GUI.
   Fix: Added a red "Stop Analysis" button next to Run Analysis.
        - runner.py: proc_holder=[None] list is populated with the Popen
          object once the process starts, giving the GUI a termination handle
        - app.py: Stop button is enabled during a run, triggers a confirmation
          dialog, then sends SIGTERM to the pipeline process
        - Status bar shows "Stopped — analysis was cancelled"

9. PVS1 Overcalling Fix (ACMG)
   File: analysis/acmg/rules.py
   Problem: PVS1 (Very Strong pathogenic) fired on any frameshift/stop-gained
            based on consequence alone, regardless of whether LoF is the
            disease mechanism for the gene. PVS1 + PM2 = Likely Pathogenic,
            so many variants were incorrectly elevated.
   Fix: eval_PVS1() now requires BOTH:
          1. Null-variant consequence (stop_gained, frameshift_variant,
             splice_acceptor_variant, splice_donor_variant, start_lost)
          2. LOFTEE high-confidence LoF (loftee_lof == "HC")
        Without LOFTEE HC, PVS1 does not fire. A reviewer flag is added:
        "LoF consequence — LOFTEE HC not confirmed (PVS1 not applied)"

10. Gene List Used as Tag Only (Not Filter)
    File: analysis/filter_engine.py
    Problem: Tier-3 variants (synonymous, UTR, intronic) outside the supplied
             gene list were hard-excluded and invisible to reviewers.
    Fix: Gene list now only sets variant.in_gene_list and variant.gene_relevance.
         It never causes exclusion. Tier-3 variants outside the gene list are
         deprioritized (soft flag), not discarded.

11. AF Filter: Deprioritize Instead of Exclude
    File: analysis/filter_engine.py
    Problem: Variants with gnomAD AF > 1% were hard-excluded, potentially
             discarding relevant variants in under-represented populations.
    Fix: Two-tier AF handling:
           AF > 5% (BA1)  -> excluded  (stand-alone benign — unchanged)
           AF 1-5%        -> deprioritized (retained, shown in own sheet)
           AF < 1%        -> retained normally
         ClinVar benign also changed from excluded -> deprioritized.
         All filtering decisions are fully traceable via exclusion_reason
         and deprioritization_reason fields.

12. QC Metrics Extracted from VCF FORMAT Column
    File: analysis/parser.py
    Problem: Read depth, genotype quality, and allele fractions were not
             captured or reported.
    Fix: Added 4 new fields to Variant dataclass:
           depth (DP), genotype_quality (GQ), allele_depth (AD), vaf
         New _extract_qc_metrics() parses these from FORMAT/sample columns.
         VAF is derived as alt_AD / (ref_AD + alt_AD).
         Low values generate reviewer flags (DP < 20, GQ < 20, VAF < 0.20).

13. Reviewer Flags Layer (New)
    Files: analysis/reviewer_flags.py (new), cli.py, config/settings.yaml
    Problem: No separation between strict ACMG classification and advisory
             guidance for reviewers. Reviewers had no structured way to
             quickly identify what needs attention.
    Fix: New module generates variant.reviewer_flags after ACMG classification.
         Flags are advisory only — they never affect ACMG classification.
         Covers: gene list membership, gnomAD rarity, CADD/REVEL/SpliceAI
         scores, LOFTEE status, ClinVar context, QC warnings, and ACMG
         context notes. Thresholds are configurable in settings.yaml under
         the reviewer_flags: section.

14. Restructured Excel Report
    File: reporting/spreadsheet.py
    Problem: Two-sheet report (Candidates + Excluded) mixed all variant
             classes together. VUS, Pathogenic, and benign were not separated.
             QC and reviewer context were absent.
    Fix: Report now has 7 sheets:
           Info            — sample metadata + mandatory disclaimer
           Priority Review — Pathogenic + Likely Pathogenic
           VUS             — all VUS (never suppressed)
           In Gene List    — other retained variants in the gene list
           High Impact     — tier1/tier2 variants outside the gene list
           Deprioritized   — AF 1-5%, tier3, ClinVar benign
           Excluded        — hard exclusions with reason
         New columns: Gene Relevance, Reviewer Flags, DP, GQ, AD, VAF,
                      Deprioritized, Deprioritization Reason.

2026-05-08 — SOP Compliance: AF Filter, ACMG Rules, Confidence, Subpop AFs
================================================================================

24. SOP AF Filter: Hard-Exclude at >1% (not deprioritize)
    File: analysis/filter_engine.py
    SOP requires common variants (>1% gnomAD AF) to be excluded, not retained
    as deprioritized. The previous 1–5% deprioritization band was removed.
    _check_af_exclusion() now uses max_af (1%) directly.
    _check_af_deprioritize() removed entirely.
    BA1 threshold (5%) is retained in the ACMG classifier only.
    6 tests updated; net test count unchanged (982).

25. AlphaMissense Added to PP3/BP4 (Anti-Correlation Groups)
    Files: config/settings.yaml, analysis/acmg/rules.py
    SOP requires AlphaMissense as an independent in-silico signal.
    PP3 and BP4 now use 3 anti-correlation groups:
      Group 1 — CADD + REVEL (correlated, shared training data) → ONE vote
      Group 2 — SpliceAI (independent) → ONE vote
      Group 3 — AlphaMissense (independent) → ONE vote
    PP3 fires when ≥2 of 3 groups vote damaging.
    BP4 fires when ≥2 of 3 groups vote benign.
    Intra-group conflict (CADD damaging + REVEL benign) cancels Group 1 vote.
    REVEL uses a three-zone model in BP4: ≥0.75 damaging, ≤0.15 benign,
    gray zone no signal. CADD uses binary cutoff in both PP3 and BP4.
    Thresholds: AlphaMissense ≥0.564 pathogenic, ≤0.340 benign (SOP).
    Rules tests updated: CADD+REVEL alone no longer triggers PP3 or BP4.

26. gnomAD Subpopulation AFs Parsed and Reported
    Files: analysis/parser.py, reporting/spreadsheet.py
    8 per-population gnomAD AFs now parsed from VEP CSQ (requires --af_gnomad):
      AFR (African), AMR (Latino), ASJ (Ashkenazi Jewish), EAS (East Asian),
      FIN (Finnish), NFE (Non-Finnish European), OTH (Other), SAS (South Asian)
    Added to Variant and TranscriptAnnotation dataclasses, copied from primary
    transcript. New columns in the spreadsheet after gnomAD AF.

27. PM2 Absence Reviewer Flag
    File: analysis/reviewer_flags.py
    When PM2 fires because gnomad_af is None (absent from gnomAD), a mandatory
    reviewer flag is added:
      "PM2: absent from gnomAD — population database coverage limitations;
       variant may be in under-represented population; manual review required"
    This alerts reviewers that absence from gnomAD is not proof of rarity in
    all populations.

28. ClinGen Validity Gating — Low Confidence + Mandatory Flags
    Files: analysis/acmg/classifier.py, analysis/reviewer_flags.py
    ClinGen gene-disease validity (Limited / Disputed / Refuted) now gates
    classification confidence:
      Definitive / Strong / Moderate → confidence from ACMG category (unchanged)
      Limited                        → confidence set to Low
      Disputed / Refuted             → confidence set to Low + mandatory reviewer flag
    New _compute_confidence() function in classifier.py; called in classify_all().
    variant.classification_confidence set to "High" / "Moderate" / "Low".
    Reviewer flags added for Limited / Disputed / Refuted ClinGen validity.

29. Classification Confidence Column in Spreadsheet
    File: reporting/spreadsheet.py
    New "Classification Confidence" column added after "ACMG Evidence Codes".
    Displays "High", "Moderate", or "Low" per variant.
